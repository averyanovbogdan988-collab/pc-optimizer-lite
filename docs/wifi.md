# Wi-Fi Doctor

Проверяет настройки Wi-Fi и сети в Windows и убирает то, что мешает стабильной
работе OBS, VTube Studio и игр. Ничего не меняет, пока вы явно не попросите,
и пишет бэкап перед каждым изменением.

## Запуск

Самый простой способ — двойной клик по `scripts/wifi-doctor.cmd`.
Он сам запросит права администратора и покажет меню:

```
1 - Проверить настройки Wi-Fi (ничего не менять)
2 - Проверить и убрать всё, что мешает
3 - То же + жёсткий сброс сетевого стека (нужна перезагрузка)
4 - Откатить последние изменения
```

Из PowerShell (от имени администратора):

```powershell
.\scripts\Wifi-Doctor.ps1                 # только диагностика
.\scripts\Wifi-Doctor.ps1 -Fix            # применить исправления
.\scripts\Wifi-Doctor.ps1 -Fix -Hard      # + сброс Winsock/IP и чистка hosts
.\scripts\Wifi-Doctor.ps1 -Restore last   # откатить последний запуск
```

Дополнительно: `-NoRestartAdapter` — не перезапускать адаптер после изменений
(тогда часть настроек драйвера применится только после перезагрузки).

## Что проверяется

| Проверка | Почему это мешает | Что делает `-Fix` |
|---|---|---|
| Адаптер и драйвер | Драйвер старше 3 лет — типичная причина обрывов | только сообщает |
| Отключение адаптера для экономии энергии | Адаптер засыпает: скачет пинг, рвётся стрим | `PnPCapabilities = 24` |
| Сон адаптера (SelectiveSuspend) | То же самое, но со стороны NDIS | отключает |
| Схема питания → энергосбережение Wi-Fi | Режет мощность радио на простое | ставит «максимальная производительность» |
| Power Saving Mode в драйвере | Вторая по частоте причина «лесенки» в пинге | ставит максимальную производительность |
| Roaming Aggressiveness | Агрессивный роуминг рвёт связь на ровном месте | ставит Medium |
| Предпочитаемый диапазон | Ноутбук сползает на забитые 2.4 ГГц | ставит 5 ГГц, если 5 ГГц уже работает |
| Packet Coalescing | Экономит энергию ценой задержки | отключает |
| Службы WlanSvc, Dhcp, Dnscache, NlaSvc, WcmSvc | «Оптимизаторы» отключают их пачками — Wi-Fi перестаёт работать | запускает и ставит «Автоматически» |
| Сохранённые сети с автоподключением | Ноутбук уходит на соседскую/гостевую точку | оставляет автоподключение только текущей сети |
| Открытые сети в списке | Автоцепляние к чужим хотспотам | сообщает + команда удаления |
| Случайные MAC-адреса | Ломают привязку IP, QoS и белые списки в роутере | отключает для текущей сети |
| Автоподключение к открытым точкам | Перескок на бесплатный хотспот | запрещает |
| IP-адрес, шлюз, статический IP | APIPA 169.254.x.x = интернета нет | перезапрашивает адрес |
| DNS-серверы | Мёртвый DNS от удалённого VPN: «интернет есть, сайты не грузятся» | возвращает DNS роутера |
| Прокси (WinINET и WinHTTP) | Остаётся от VPN и «ускорителей», весь трафик уходит в никуда | отключает, если прокси не отвечает |
| Файл hosts | Кряки и «оптимизаторы» блокируют домены — лаунчер молча не работает | комментирует блокирующие строки |
| Виртуальные адаптеры и метрики | VPN/Hamachi/VirtualBox перехватывают маршрут | понижает их приоритет |
| Автонастройка окна TCP | «Твик из интернета», режет скорость в разы | возвращает `Normal` |
| Эвристики масштабирования окна TCP | Windows сама зажимает окно приёма до 64 КБ — падает только загрузка | отключает |
| Автонастройка через групповую политику | Политика сильнее локальной настройки, обычная правка не действует | только сообщает |
| Сторонний антивирус с проверкой веб-трафика | Прогоняет через себя входящее, режет загрузку в 2-3 раза | только сообщает |
| Приёмные буферы адаптера | Рывки и просадки при загрузке | только сообщает |
| RSS | Вся сеть на одном ядре — фризы на стриме | включает |
| MTU | Обрезанные пакеты: полузагруженные сайты, заикание в голосе | возвращает 1500 |
| QoS: резерв полосы и политики-ограничители | Прямое ограничение скорости | снимает резерв, про политики сообщает |
| Delivery Optimization | Windows раздаёт обновления и забивает аплоад стрима | запрещает раздачу |
| Лимитное подключение | Windows и приложения режут себе трафик | снимает отметку |
| Тип сети (Общедоступная) | Не работает NDI для OBS, стрим на локальные устройства | сообщает + готовая команда |
| Брандмауэр: блок исходящих | Ничего не выходит в интернет без явного правила | разрешает исходящие |
| Сторонние сетевые фильтры | VPN, Killer, NetLimiter, SmartByte режут скорость | сообщает |
| Сигнал, канал, загруженность эфира | Слабый сигнал не лечится настройками | сообщает |
| История обрывов за 7 дней | Показывает, насколько всё плохо на самом деле | сообщает |

## Если загрузка медленнее отдачи

Отдельный случай, который стоит понимать. Отдачу ограничивает окно приёма
сервера, а загрузку — окно приёма вашего компьютера. Поэтому всё, что зажимает
приёмный тракт Windows, роняет **только загрузку**, оставляя отдачу целой:

- отключённая автонастройка окна TCP или включённые эвристики масштабирования —
  окно фиксируется на 64 КБ, и скорость упирается в `64 КБ / RTT` на поток;
- проверка веб-трафика сторонним антивирусом;
- отключённый RSS и маленькие приёмные буферы адаптера.

Прикинуть потолок можно так: при пинге под нагрузкой 65 мс окно 64 КБ даёт
около 8 Мбит/с на соединение, а Speedtest качает в 8 потоков — отсюда
характерные ~65 Мбит/с при исправной отдаче в сотни мегабит.

Все эти пункты проверяются в разделе отчёта «Приём данных».

## Бэкап и откат

Перед каждым изменением прежнее значение пишется в
`%LOCALAPPDATA%\pc-optimizer-lite\wifi-backup-<дата>.json`.
Туда же кладётся отчёт `wifi-report-<дата>.txt` и копия `hosts`, если он менялся.

Откат применяет записи в обратном порядке:

```powershell
.\scripts\Wifi-Doctor.ps1 -Restore last
# или конкретный файл:
.\scripts\Wifi-Doctor.ps1 -Restore "$env:LOCALAPPDATA\pc-optimizer-lite\wifi-backup-2026-01-01_12-00-00.json"
```

## Что скрипт НЕ делает сам

Намеренно, чтобы не сломать рабочую конфигурацию:

- не удаляет профили Wi-Fi (только выключает автоподключение);
- не меняет тип сети с «Общедоступная» на «Частная» — это решение по безопасности;
- не удаляет политики QoS и не отключает сетевые фильтры;
- не трогает hosts, если в нём больше 50 блокировок (похоже на осознанный
  список блокировки рекламы) — только с ключом `-Hard`;
- не выполняет `netsh winsock reset` без ключа `-Hard`.
